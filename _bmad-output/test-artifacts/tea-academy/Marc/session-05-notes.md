## Key Concepts Covered

1. **ATDD:** Red phase = write failing acceptance tests first; acceptance = criteria from the story (automated), not manual execution. Often E2E for end-user US, API for API-consumer US.
2. **Automate:** Code exists first → generate tests to expand coverage (vs ATDD: tests first, then code).
3. **Component TDD:** Red → Green → Refactor loop; test defines behavior.
4. **API testing:** Fast, business logic, response/schema validation; pattern with request.get, expect response.

## Key Takeaways

- Acceptance test = automated test that encodes an acceptance criterion (E2E or API depending on story beneficiary).
- ATDD = acceptance tests first (red), then implement (green); Automate = add tests to existing code.
- API tests: fast, direct business-logic validation; use when the “acceptance” is at API level.
