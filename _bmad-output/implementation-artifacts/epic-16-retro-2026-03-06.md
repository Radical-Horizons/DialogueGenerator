## 🔧 Défis et Apprentissages

### 1. SoT frontend : document vs projection

En 16.4, le save envoyait la re-sérialisation de la projection (graphToDocument/buildLayoutFromNodes) au lieu du document et du layout en mémoire. Risque : dérive, champs perdus, incohérence avec l’ADR-008. **Apprentissage :** toute action qui persiste doit utiliser explicitement la SoT (state.document, state.layout) ; les tests doivent vérifier le payload envoyé (pas seulement « putDocument appelé »).

### 2. Synchronisation document lors des opérations graphe

addNode, connectNodes, disconnectNodes en mode document SoT ne mettaient à jour que nodes/edges, pas le document. Dérive possible jusqu’au prochain load. **Apprentissage :** en mode SoT document, toute modification du graphe (add/connect/disconnect) doit mettre à jour le document (et le layout si positions) puis recalculer la projection.

### 3. File List vs git

Plusieurs stories ont eu des fichiers modifiés (git) non listés dans la File List de la story. **Apprentissage :** confronter File List et `git status` en fin de story ; documenter les fichiers hors périmètre (cache, outputs) pour éviter le bruit.

### 4. E2E et fixtures

En 16.6, le spec E2E utilisait `readFixtureViaApi` (inexistant) ; réécriture du spec avec seed via PUT /documents et pattern aligné sur les autres specs. **Apprentissage :** réutiliser les helpers E2E existants (ex. readDialogueViaApi) et documenter les limites (ex. déconnecter partiellement couvert).
