## 1. Résumé exécutif

- **Livraison :** périmètre fonctionnel complet pour la validation avant export : structure des nœuds, contenu vide, lore explicite / signaux humains pour incohérences, orphelins, cycles, juge LLM, détection d’« AI slop », context dropping configurable, simulation de flux (dead ends), rapport de couverture de simulation, **conformité schéma Unity 100 %** (FR48), puis **refactor des routeurs graphe** (4.14) pour sortir d’un god-file et sécuriser la maintenabilité.
- **Valeur utilisateur :** filet de qualité multi-couches sur le graphe — du statique au comportemental (simulation) jusqu’à la conformité du JSON Unity, sans obliger l’utilisateur à tout relire à la main.
- **Epic suivant :** Epic 5 (export Unity) — dépend explicitement d’Epic 4 (validation pré-export, notamment schéma).

---

## 2. Ce qui a bien marché

- **Réutilisation des briques existantes :** plusieurs stories s’appuient sur `GraphValidationService`, `GraphConversionService`, `validate_unity_json` / `unity_schema_validator`, plutôt que de dupliquer la logique (ex. 4.13).
- **Patterns UI réutilisables :** reproduction du couple bouton + panneau (ex. simulation de flux → validation schéma) limine la dette UX et accélère les stories tardives de l’épique.
- **Garde-fous d’architecture récurrents :** handlers minces dans les routers, logique dans `services/`, injection via `Depends` / container, pas de singleton résiduel pour les règles context dropping après vérification (4.14).
- **Story 4.14 au bon moment :** une fois les endpoints de validation / qualité stabilisés, le découpage `graph_io`, `graph_cost`, `graph_validation`, `graph_quality`, `graph_flow`, `graph_node_history`, etc. évite d’empiler encore sur un fichier monolithique.
- **Barre qualité tests :** pytest ciblé sur les endpoints + Vitest sur les panneaux critiques ; consigne « pas de données GDD réelles en CI » respectée dans les fiches.

---

## 3. Défis et apprentissages (synthèse des fiches stories)

**Surface API / graphe**

- L’épique a **concentré beaucoup de surface** sur le namespace graphe : chaque nouvelle capacité touchait routers, schémas Pydantic, store / toolbar — d’où l’intérêt du refactor 4.14.

**Complexité produit (validation « intelligente »)**

- **LLM judge, slop, context dropping :** sujets sensibles au bruit, au coût et aux faux positifs ; les stories insistent sur des paramètres configurables et des chemins de review humaine (FR39) là où c’est pertinent.

**Cohérence Unity v1.1.0**

- **choiceId**, document vs liste legacy, `ensure_ascii=False` : les dev notes de 4.13 rappellent de ne pas casser le format — critique pour la transition vers Epic 5.

**Patterns récurrents (plusieurs stories)**

- « Copier le pattern FlowSimulation » côté front ; « handler ≤ ~30 lignes + délégation service » côté back.
- Vigilance sur **fichiers déjà très longs** (`GraphEditorHeader`, ancien `graph.py`) : changements minimaux ciblés jusqu’au split.
