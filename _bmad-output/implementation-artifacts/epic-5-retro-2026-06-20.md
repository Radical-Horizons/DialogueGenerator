## 4. Ce qui a bien marché

- **Engagements Epic 4 tenus :** traçage export → validateur (`unity_export_validation_service`) ; messages FR alignés ; batch réutilise le même verdict que `validate-schema` et `write_unity_dialogue_to_file`.
- **Extraction de hooks dédiés :** `useUnityExport`, `useUnityExportDownload`, `useBatchUnityExport`, `buildGraphApiPayload`, `graphApiErrors` — évite d'alourdir `GraphEditorHeader` malgré sa taille (~1 600 L).
- **Pattern bibliothèque vs graphe :** batch lit documents persistés ; graphe passe par validate → `save-and-write` — décision SM 5.2 claire et respectée.
- **Revues code efficaces :** bugs silencieux (toast succès sans écriture, option UI sans effet, logs absents sur OSError) attrapés avant merge.
- **Réutilisation Epic 4 :** `SchemaValidationPanel`, `handleSchemaErrorClick`, split routers graphe — pas de god-file réintroduit.
- **Logs export :** `ExportLogService` + router `exports.py` + UI `ExportLogsPanel` miroir `GenerationLogsPanel` — cohérence UX.

## 5. Défis et apprentissages (synthèse stories)

### Patterns récurrents

| Thème | Occurrences | Détail |
|-------|-------------|--------|
| Handlers ≤ 30 L vs croissance `dialogues.py` | 5.1–5.6 | Logique bien déléguée aux services, mais `dialogues.py` ~832 L — risque de re-monolithisation |
| Fichiers frontend « chauds » | 5.1–5.6 | Consigne répétée : **ne pas** toucher `GraphEditorHeader` pour batch/logs — respectée |
| Validateur unique | 5.1, 5.3 | Unification `validate_unity_json` + GDD flags — évite divergence preview/export/batch |
| Code review HIGH | 5.1, 5.4, 5.6 | seq, filenameStrategy, journalisation échecs |

### Complexité technique

- **Sérialisation graphe → Unity :** champs optionnels exportés comme `null` ou chaînes vides (`condition`, deltas FR94) alors que le schéma JSON les rejette — friction sur **données legacy** et fixtures e2e.
- **Preview vs export :** 5.5/5.6 ont clarifié : preview sans log ; export depuis modal = export réel loggé.
- **ZIP batch :** stdlib Python côté serveur (pas JSZip) — bon choix KISS 5.4.

### Breakthrough

- **Story 5.3** : `unity_export_validation_service` comme point d'entrée unique — base durable pour Epic 6+ et tout nouveau chemin d'export.

## 7. Aperçu Epic 6 (préparation)

**Titre :** Templates et réutilisabilité (FR55–63)

**Dépendances sur Epic 5 :**

- Templates généreront des dialogues devant passer le **même validateur export** avant livraison Unity.
- Preview export (5.5) utile pour inspecter output template avant batch.
- Logs export (5.6) pour tracer exports post-génération template.

**Préparation critique :**

1. **Normalisation sérialisation export** — omettre ou normaliser `influenceDelta`/`respectDelta` null, choix vides `__idx_*`, conditions vides — sinon templates amplifient le taux d'échec validation.
2. **Story ou spike migration** dialogues legacy `Assets/Dialogue/*.json` vers schéma v1.2.0 (hors Epic 6 fonctionnel mais bloque l'usage réel).
3. **Ne pas étendre `dialogues.py`** — nouveaux endpoints templates dans router dédié (pattern `exports.py`).
4. **Réutiliser** `ExportPreviewModal` / validation document pour QA templates.

**Risque significatif :** Epic 6 sans (1) laisse l'utilisateur croire que « l'export est cassé » alors que le gate fonctionne sur du contenu non conforme.

## 8. Découverte significative

**Oui — mise à jour plan recommandée (non bloquante pour démarrer Epic 6, bloquante pour promesse « 0 % invalid exports » en prod).**

| Découverte | Impact |
|------------|--------|
| Dialogues persistés legacy non conformes schéma v1.2.0 | Export batch et single **bloquent correctement** — UX « tout échoue » sur bibliothèque réelle |
| Sérialiseur émet `null`/"" rejetés par JSON Schema | Faux négatifs sur dialogues **édités dans le graphe** (fixture e2e mobile : 24 erreurs) |
| NFR-P3 non mesuré en CI | Risque perf non détectée sur gros dialogues |

**Recommandation :** ajouter une story **5.x ou 4.x follow-up** « normalisation export + migration legacy » **avant** ou **en parallèle** des premières stories Epic 6.

## 11. Enseignements clés

1. **Un validateur, plusieurs portes** — centraliser tôt évite les bugs « preview OK / export KO ».
2. **Code review sur flux silencieux** — `seq`, filenameStrategy, logs OSError : des succès UI mensongers.
3. **Le gate expose la dette contenu** — Epic 5 révèle que les JSON sur disque ne sont pas prêts Unity ; c'est une victoire du gate, pas un échec de l'epic.
4. **Hooks > header** — la discipline « ne pas toucher GraphEditorHeader » a permis de livrer 6 stories sans refactor massif.
