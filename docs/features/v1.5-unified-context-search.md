## Problème Actuel (au moment de la rédaction — partiellement adressé en v1.8.4)

L'interface actuelle utilise des **onglets séparés** pour chaque catégorie de contexte (Personnages, Lieux, Objets, Espèces, Communautés). Pour sélectionner des éléments de catégories différentes, l'utilisateur doit :

1. Naviguer vers l'onglet "Personnages"
2. Sélectionner les personnages
3. Naviguer vers l'onglet "Lieux"
4. Sélectionner les lieux
5. Répéter pour chaque catégorie

**Friction identifiée :**
- Changements d'onglets répétitifs (3-5 clics pour une configuration complète)
- Recherche séquentielle (impossible de chercher "Léviathan" et voir tous les résultats d'un coup)
- Mental model fragmenté (contexte = ensemble cohérent, pas des catégories isolées)

**Problème technique sous-jacent :**
- Recherche actuelle = chargement de tous les JSON + parsing + filter (LENT : 2-5 secondes)
- Pas d'indexation pour recherche rapide
- Métadonnées riches disponibles mais pas exploitables efficacement

## Solution Proposée : Vue Unifiée avec Recherche Rapide

### Vision UX

**Une seule vue** remplaçant les onglets, avec :
- **Recherche unifiée** qui cherche dans toutes les catégories simultanément
- **Filtres combinables** par type (Personnages, Lieux, etc.) et par métadonnées (Région, Sprint, etc.)
- **Résultats hiérarchisés** : correspondances exactes dans le nom en premier, puis correspondances dans le contenu
- **Sélection multi-catégories** rapide dans une seule vue

## Architecture Technique

### Prérequis : SQLite (V1.5)

La migration SQLite prévue pour V1.5 permettra :
- Indexation native avec FTS5 (Full-Text Search)
- Requêtes rapides (<200ms même sur grandes bases)
- Persistance structurée
- Fondation pour d'autres features (historique, analytics, etc.)

### Schema SQLite

#### Table `gdd_items`

Table principale contenant tous les éléments du GDD indexés.

```sql
CREATE TABLE gdd_items (
    id TEXT PRIMARY KEY,                    -- UUID ou nom normalisé
    name TEXT NOT NULL,                     -- Nom de l'élément
    type TEXT NOT NULL,                     -- 'character', 'location', 'item', 'species', 'community'
    category TEXT,                          -- Catégorie (ex: "Personnages", "Lieux")
    region TEXT,                            -- Région associée (ex: "Léviathan pétrifié")
    sprint TEXT,                            -- Sprint (ex: "Sprint 2")
    metadata_json TEXT,                     -- JSON avec toutes les métadonnées (Alias, Espèce, etc.)
    full_text TEXT,                         -- Texte complet indexable (Résumé + sections clés)
    token_count INTEGER,                    -- Nombre de tokens estimé
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_gdd_items_type ON gdd_items(type);
CREATE INDEX idx_gdd_items_region ON gdd_items(region);
CREATE INDEX idx_gdd_items_sprint ON gdd_items(sprint);
CREATE INDEX idx_gdd_items_category ON gdd_items(category);
```

#### Table FTS5 pour recherche full-text

```sql
CREATE VIRTUAL TABLE gdd_items_fts USING fts5(
    name,
    alias,                                  -- Extrait de metadata_json
    full_text,
    content='gdd_items',
    content_rowid='rowid'
);
```

**Trigger pour maintenir l'index FTS :**
```sql
CREATE TRIGGER gdd_items_fts_insert AFTER INSERT ON gdd_items BEGIN
    INSERT INTO gdd_items_fts(rowid, name, alias, full_text)
    VALUES (new.rowid, new.name, json_extract(new.metadata_json, '$.Alias'), new.full_text);
END;

CREATE TRIGGER gdd_items_fts_delete AFTER DELETE ON gdd_items BEGIN
    INSERT INTO gdd_items_fts(gdd_items_fts, rowid, name, alias, full_text)
    VALUES('delete', old.rowid, old.name, json_extract(old.metadata_json, '$.Alias'), old.full_text);
END;

CREATE TRIGGER gdd_items_fts_update AFTER UPDATE ON gdd_items BEGIN
    INSERT INTO gdd_items_fts(gdd_items_fts, rowid, name, alias, full_text)
    VALUES('delete', old.rowid, old.name, json_extract(old.metadata_json, '$.Alias'), old.full_text);
    INSERT INTO gdd_items_fts(rowid, name, alias, full_text)
    VALUES (new.rowid, new.name, json_extract(new.metadata_json, '$.Alias'), new.full_text);
END;
```

#### Table `user_favorites` (optionnel V1.5)

```sql
CREATE TABLE user_favorites (
    user_id TEXT NOT NULL,
    item_id TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (user_id, item_id),
    FOREIGN KEY (item_id) REFERENCES gdd_items(id)
);
```

### Service Backend : `SearchIndexService`

**Responsabilité :** Indexer et rechercher dans le GDD de manière efficace.

**Méthodes principales :**
```python
class SearchIndexService:
    def rebuild_index(self) -> None:
        """Rebuild l'index complet depuis les fichiers GDD JSON."""
        # 1. Parcourir tous les fichiers GDD
        # 2. Extraire métadonnées + texte indexable
        # 3. Insérer/mettre à jour dans SQLite
        # Appelé au démarrage de l'app ou quand GDD change
        
    def search(
        self,
        query: str,
        filters: Optional[Dict[str, Any]] = None,
        limit: int = 50
    ) -> List[SearchResult]:
        """Recherche dans l'index avec filtres."""
        # Utilise FTS5 pour recherche rapide
        # Applique filtres (type, région, sprint, etc.)
        # Trie par pertinence (exact match dans nom > contenu)
        
    def get_by_id(self, item_id: str) -> Optional[GDDItem]:
        """Récupère un élément par ID."""
        
    def get_favorites(self, user_id: str) -> List[GDDItem]:
        """Récupère les favoris de l'utilisateur."""
```

**Rebuild Index :**
- **Quand :** Au démarrage de l'app (si index absent ou obsolète)
- **Performance cible :** <5 secondes pour indexer ~2000 éléments
- **Incrémentiel :** Détecter changements dans fichiers GDD (timestamp) et mettre à jour uniquement les éléments modifiés

**Recherche :**
- **Performance cible :** <200ms pour une recherche avec filtres
- **Pertinence :** 
  1. Exact match dans `name` (priorité maximale)
  2. Match dans `alias` (priorité haute)
  3. Match dans `full_text` (priorité normale)
  4. Fuzzy match (si pas de résultats exacts)

### API Endpoints

#### `GET /api/v1/context/search`

Recherche unifiée dans toutes les catégories.

**Query Parameters :**
- `q` (string, required) : Terme de recherche
- `types` (string[], optional) : Filtrer par types (`character`, `location`, `item`, etc.)
- `regions` (string[], optional) : Filtrer par régions
- `sprints` (string[], optional) : Filtrer par sprints
- `favorites_only` (boolean, optional) : Uniquement favoris
- `limit` (integer, optional, default: 50) : Nombre max de résultats

**Response :**
```json
{
  "results": [
    {
      "id": "seigneuresse-uresair",
      "name": "Seigneuresse Uresäir",
      "type": "character",
      "category": "Personnages",
      "region": "Léviathan pétrifié",
      "sprint": "Sprint 2",
      "token_count": 2100,
      "preview": "Première rencontre in-game...",
      "match_reason": "exact_name" // "exact_name", "alias", "content"
    }
  ],
  "total": 15,
  "query": "uresair",
  "filters_applied": {
    "types": ["character"],
    "regions": ["Léviathan pétrifié"]
  }
}
```

#### `GET /api/v1/context/items/{id}`

Récupère les détails complets d'un élément (pour prévisualisation dans tooltip).

**Response :** Même structure qu'un élément GDD complet (depuis JSON).

#### `POST /api/v1/context/favorites/{id}`

Ajoute un élément aux favoris.

#### `DELETE /api/v1/context/favorites/{id}`

Retire un élément des favoris.

## Spécifications UX Détaillées

*(À créer en V1.5 avec wireframes Excalidraw)*

### Composants UI

1. **Barre de recherche** : Input avec placeholder "Rechercher des personnages, lieux, objets..." (Ctrl+K)
2. **Chips de filtres** : Filtres combinables (Type, Région, Sprint, Favoris)
3. **Liste de résultats** : Items avec checkbox, icône, nom, métadonnées, token count
4. **Footer** : Total tokens sélectionnés, actions (Sélections actives, Tout effacer)

### Interactions

- **Recherche en temps réel** : Résultats affichés pendant la frappe (debounce 300ms)
- **Keyboard navigation** : ↑↓ pour naviguer, Espace pour sélectionner, Enter pour prévisualiser
- **Filtres combinables** : Plusieurs filtres actifs simultanément
- **Tooltip au hover** : Aperçu détaillé de l'élément (sans charger la page complète)

### Hiérarchisation des Résultats

**Ordre de tri :**
1. **Correspondances exactes dans le nom** (mis en valeur visuellement : gras, couleur)
2. **Correspondances dans l'alias**
3. **Correspondances dans le contenu**
4. **Favoris** (toujours affichés en haut si match partiel)

## Migration depuis l'Ancienne Interface

### Backward Compatibility

L'ancienne interface (onglets séparés) peut coexister avec la nouvelle :
- **Option A** : Toggle "Vue unifiée" / "Vue classique" (migration progressive)
- **Option B** : Remplacer complètement (cleaner, mais breaking change)

**Recommandation :** Option B (remplacement complet) car la nouvelle interface est strictement meilleure.

### Données Existantes

- **Sélections en cours** : Migrer automatiquement (si session active, préserver les sélections)
- **Favoris** : Nouveau système (vide au départ, utilisateurs peuvent ajouter leurs favoris)

## Notes Techniques

### Performance

- **Index initial** : <5 secondes pour ~2000 éléments
- **Recherche** : <200ms avec filtres
- **Rebuild incrémental** : Détection de changements (timestamp fichiers) + update uniquement modifiés

### Scalabilité

- **Limite actuelle** : ~5000 éléments (performance acceptable)
- **Au-delà** : Partitioning par type ou région (optimisation future)

### Sécurité

- **Favoris** : Scoped par utilisateur (isolation des données)
- **Recherche** : Pas de données sensibles dans l'index (uniquement contenu GDD public)
